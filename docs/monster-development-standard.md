# 怪物开发规范

确认日期：2026-10-30。适用于后续怪物新增、技能扩展和已有怪物改造。

本文是开发约束，不表示其中所有能力已经实现。本轮仅制定规范，不新增怪物、GA、预警组件或出怪逻辑。

## 1. 复用优先与开发范围

- 本开发路径采用现有 Actor/GAS 敌人架构，复用 `AEnemyCharacter`、`BP_EnemyBase`、ASC、属性、阵营、伤害、AIController、行为树及对象池接入机制。
- 优先通过配置、子类与小幅扩展实现差异：模型、AnimBP、蒙太奇、技能组合、属性、AI策略及表现资源。不得为每只怪物复制整套 ASC、AI 或伤害流程。
- 资源包中的示例角色蓝图不自动视为可用敌人。先核实父类、依赖、骨骼兼容性、动画绑定、碰撞和编译状态，再决定复用范围。
- 公共机制确需修改时，说明现有机制缺口、影响范围和回归项。怪物专属参数和表现使用独立配置；保留源素材与其他怪物的调参。
- 不因导入怪物而切换至 PureMass，也不将 Actor 对象池规则直接套给 Mass 实体。另一路径须单独明确设计。

## 2. 每只怪物的设计记录

开发前记录以下内容，并随实现更新：

| 项目 | 必须明确的内容 |
|---|---|
| 身份与定位 | 稳定标识、普通/精英/Boss定位、出现条件、可否入池 |
| 资源 | 模型、骨骼、AnimBP、移动/攻击/受击/死亡动画，蒙太奇Slot、插槽、Root Motion策略 |
| 逻辑复用 | 父类、ASC初始化、技能授予、AI选择技能的入口及必要差异 |
| 每个攻击 | 目标规则、作用形状、伤害、消耗、冷却、前摇/生效/后摇、打断条件 |
| 预警与表现 | 感叹号/红色范围/两者组合，出现与消失时刻、锁定时机、特效资源与位置 |
| 生命周期 | 死亡表现、回收条件、复用重置项，外部持续效果的归属与处理 |
| 验收 | 自动化用例、PIE步骤、测试证据和未验证项目 |

不统一强制所有怪物使用相同前摇秒数或伤害数值；具体值由技能设计确定，但必须留出可辨识、可反应的提示过程。

## 3. 统一攻击生命周期

攻击按“选定目标 → 预警/前摇 → 生效 → 后摇 → 结束”设计。预警可覆盖前摇，但必须早于首次伤害或危险位移，不得与首段伤害同帧才出现。

- 明确每阶段是否允许移动、转向、重新选目标和被打断。
- 明确何时锁定方向或落点。锁定前追踪目标时提示必须同步；锁定后不得无提示改变攻击范围。
- 只有一个实际执行入口；消耗、冷却和伤害不得由GA、动画通知与蓝图各执行一遍。
- 动画命中窗口与生效时机一致。使用蒙太奇/Notify时需处理打断、未收到通知和重复通知。
- 服务端决定攻击阶段、实际目标与伤害。表现只反映该结果，不另行决定命中；多人场景中客户端应观察到一致的预警与锁定结果。
- 正常结束、取消、死亡和回收均有明确收尾路径；取消后不得遗留未来伤害任务。

## 4. 攻击预警：确认的默认规则

**每次攻击都必须有预警。**

| 攻击类型 | 默认预警 |
|---|---|
| 普通单体攻击 | 怪物头上显示感叹号 |
| 范围攻击 | 红色实际作用范围 |
| 位移攻击（冲锋、扑击等） | 红色实际危险路径或落地区域 |
| 特殊技能 | 可同时使用感叹号和红色范围提示 |

分类按实际行为确定：普通攻击若包含范围伤害，也必须显示范围；不能仅因名称为“普攻”而省略范围提示。

### 感叹号

- 绑定可配置的头部插槽或相对偏移，适配不同身高与模型比例。
- 在预警阶段可辨识；预警结束、攻击取消、死亡或回收时撤销。
- 不参与碰撞、目标筛选或伤害；避免多次激活叠出重复图标。

### 红色实际作用范围

- 预警与伤害查询共用同一份形状定义和参数，包含中心、方向、半径、内圈、长度、宽度、角度及必要的高度限制。不得各自硬编码一套数值。
- 圆形、环形、扇形、直线、冲锋路径与落点应对应真实判定。环形安全内圈必须可见，不能画成全圆伤害区。
- 红色地面提示应正确贴地；墙体、楼层、坡面或路径阻挡不得造成明显的“显示安全但实际命中”。复杂场景需要明确可视化方式和测试边界。
- 位移攻击显示实际可能造成伤害的路径/扫掠范围；单纯移动目的地不等于攻击作用范围。
- 预警到生效时切换为命中或持续危险表现，避免残留预警混淆阶段。纯装饰粒子可以超出边界，但不能取代清晰的判定范围标识。
- 使用 Free_Spells 或其他特效包时核实本地/世界空间、用户缩放参数、粒子寿命、循环与自身扩张动画；不能只赋一个 Niagara 引用或缩放组件就宣称范围匹配。

### 多段与持续攻击

- 连招每次出现新的攻击方向、落点或作用范围，都必须让玩家提前辨识；不能只提示第一段而无提示增加新威胁。
- 共享一段预警的连续攻击必须明确完整危险范围和节奏；持续伤害区域在有效期间保持清晰的危险标识。
- 延迟爆发、追踪落点和扩散波明确其预警、锁定及波前规则；视觉扩张速度与实际伤害推进一致。

## 5. 死亡与对象池

**判定死亡、死亡表现、回收和销毁必须分开。** 具体接口沿用正在维护的对象池实现，不为新怪物另建平行池。

- 每次生命只允许一次死亡结算、击杀奖励、掉落与遭遇计数通知。
- 死亡时停止新攻击和AI决策，取消本次生命尚未生效的攻击、任务与预警。死亡表现可以继续播放，但不继续执行活体战斗逻辑。
- 池化怪物不得默认使用不可恢复的销毁、武器脱落、溶解时间线或自动LifeSpan。若采用这些表现，必须有完整可验证的恢复方案，并与池实现兼容。
- 当前池约定是普通怪按生成请求选择加入；同一蓝图可能也用于非池化精英，不能根据蓝图类型推断入池资格。保留非池化敌人的正常销毁路径。
- 当前池支持死亡后短暂保留布娃娃、武器保持附着，然后隐藏休眠；再次激活恢复骨骼组件附着、变换、碰撞和动画。死亡动画等新表现可替换视觉阶段，但必须满足统一回收合同。
- 遵循当前“后续遭遇才允许复用”的隔离策略，不擅自改为同遭遇立即复用。

### 回收与重新激活的合同

| 阶段 | 必须处理 |
|---|---|
| 回收前 | 取消活跃GA、AbilityTask、攻击计时器与异步任务；解绑本次生命委托；清除AI目标、路径与黑板临时数据；停止预警、循环特效和音效；处理临时GE/标签及拥有的技能实体 |
| 池中休眠 | 不继续攻击、索敌、碰撞或产生伤害；仅在约定的尸体阶段保留必要物理表现，正式闲置后关闭无用Tick和物理 |
| 再次激活 | 恢复属性、活体标签、碰撞、移动、动画、物理与AI；重新设置房间/目标状态；不得重复授予GA、重复绑定委托或遗留旧冷却 |

区分应长期保留的技能授予/基础属性与每次生命的临时状态，不以“清空整个ASC”代替正确重置。

延迟回调、投射物及持续效果必须能够识别所属生命/池租约；旧生命的回调不得影响重新激活后的角色。对已施加到其他Actor上的持续效果，逐技能明确死亡后继续或撤销策略；若继续，必须隔离旧来源，不能把新生命当成旧施法者。现有池对这类外部持续效果仍有验证边界，新怪物不能据此假定已安全支持。

## 6. 接入顺序与测试门槛

1. 检查真实资产、现有敌人与最新池/生成配置，记录复用关系和缺口。
2. 确定怪物与技能行为、动画窗口、预警和死亡/回收合同。
3. 实现最小必要逻辑，并验证目标过滤、伤害、消耗、冷却、打断与结束。
4. 匹配动画与特效，核对预警位置、锁定时机、实际范围和清理。
5. 通过匹配变更范围的自动化测试后，接入当前游戏生成配置；不擅自增加怪物总量或改变既定池容量/分配策略。
6. 提供逐技能PIE步骤，由用户完成最终验收。测试未覆盖项明确保留。

每只怪物至少检查：正常攻击；前摇打断；攻击中死亡；冷却重复拒绝；无效目标/友军过滤；范围边界与墙体；死亡只结算一次；回收后再生成；旧回调不污染新生命；没有残留预警、伤害、GE或重复委托。池化怪物至少经历两次生命，不能仅验证首次生成。

涉及联机变化时补测服务端一次结算、客户端预警一致、死亡和复用表现同步。NullRHI或配置读回不能代替预警可读性、贴地精度及动画节奏的PIE视觉验收。
