# 萨满实现记录

遵循 monster-development-standard.md 与已确认 monster-wave1-design.md。2026-10-31，首版仍在验证，不代表已接入出怪名单。

## 资源与技能

独立目录 `/Game/BluePrints/Characters/Goblin/ShamanExpansion`。复用原萨满模型、AnimBP、法杖以及 EnemyCharacter ASC/伤害路径，创建专属角色、数据资产、GA 和独立动画。采用通用攻击选择器互斥执行，旧 GA_SummonAbility 的 Delay/Notify 生成链不与新链同时授予。

源蒙太奇攻击事件在0.585375s，召唤事件在0.363225s；首版取邻近帧。事件位置是候选依据，仍需实际输出与特效验证。独立副本移除旧事件，只有原生蒙太奇时钟产生一次生效。保留根骨骼旋转，只归一化根平移，角色在施法期间停步。

单体距离650cm、倍率0.8；爆发锁定目标脚下半径170cm、倍率1.2。基础伤害25、伤害类型为现有 Damage.Magic。锁定后爆发不再追踪目标。施法入口校验视线，单体生效再按范围和遮挡筛选。

## 召唤与池合同

原召唤一次5只，距离75–300cm、前方90度。沿用数量和落点区间，首版召唤已制作的恶魔，最多存活5只。对单只配置避免除以零；禁止召唤萨满子类形成递归。位置需贴地、可达、无遮挡，碰撞无法调整时放弃该落点，不强行重叠生成。

召唤在服务端一个已预警的蒙太奇生效点执行；参数按施法快照读取，逐次生成检查来源租约。没有跨生命 Delay 队列。召唤物记录来源及租约，死亡/销毁均只移除一次记录。来源死亡、回收或结束时撤销剩余召唤物，旧死亡回调不修改新生命计数。

房间模式走 Director 的受控召唤入口：只允许当前遭遇中已登记的活体来源，生成点必须属于当前房间，召唤物作为可回收的可选遭遇目标登记；与普通/精英/待生成单位共用30个目标上限。来源清理先以 Recycled 结算，再销毁，避免把正常清理计作 Unexpected。召唤物不加入普通怪池，不改变既定池容量和初始出怪总量。房间结束会统一回收它们。

来源通过独立 `SummoningSource` 弱引用记录，不能用 Actor Owner：APawn 在 AI 接管后会把 Owner 改成 Controller。落点除导航投影外还必须通过禁止部分路径的完整路径检查。

非房间隔离测试仍支持相同来源归属与死亡清理，但不能替代真实房间计数验证。狭窄地形或碰撞可能只找到少于5个安全落点，因此每次生成数量为0–5，不能用强行重叠补足5只。
