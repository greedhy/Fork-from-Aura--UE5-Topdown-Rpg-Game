# 怪物制作流程：StoneGolem 经验基线

更新：2026-10-31。本文是可重复执行的制作流程，约束以 [怪物开发规范](monster-development-standard.md) 为准；GA 制作沿用 [build-ga](../skills/build-ga/SKILL.md)。

## 1. 盘点真实资源

运行 `Scripts/GA/audit_enemy_candidates.py`，读取本轮唯一编号的 inventory.json。记录模型、骨骼、移动/攻击/受击/死亡动画、AnimBP、物理资产、插槽与依赖错误。区分独立怪物、换肤和演示角色。资源包示例蓝图不直接作为游戏敌人。

检查最新 EnemyCharacter、对象池与生成配置；记录当前工作区变更、编辑器 PIE、未保存资产和测试前地图。不能依据旧文档推断池接口仍然相同。只备份并修改本任务拥有的资产；未知工具结果先读回，不盲目重复写入。

## 2. 建立每只怪物的设计卡

明确定位、候选出现位置、父类、AI/ASC复用关系、技能列表和死亡回收方案。调参放独立 UE DataAsset 或 DataTable，至少含速度、基础伤害、攻击距离、权重、冷却、伤害倍率、预警形状和时序。不要复制 StoneGolem 专属锤盾依赖来伪装通用怪物。

每个 GA 填写：目标与过滤、源动画和截取段、预警开始、动画开始、锁定、命中窗口、后摇、取消条件、特效位置与寿命。没有逐帧预览前，时间只能标为候选，不能视为已确认。

## 3. 先确认动作，再实现技能

用实际模型、武器与地面预览移动和攻击；测接触帧、武器轨迹、根位移和混合。组合攻击应截取独立片段；触地不成立时使用专属副本修姿态，或明确修改技能设计，不改源素材。

移动 AnimBP 使用实际速度驱动，核实 Slot 到输出姿态链。BlendSpace 写入 Samples 不代表运行时已生成插值缓存：重建、保存，重启后实际播放并比较脚部位置。蒙太奇播放失败、提前打断或错过命中窗口不能照样结算伤害。

## 4. 最小实现与资产制作

复用 EnemyCharacter、现有 ASC/伤害 GE、AIController 和行为树；必要差异使用独立配置和小幅扩展。新反射类型先完整构建、加载，再创建引用资产。制作脚本可重入，独立目录存放怪物 BP、GA、调参资产、蒙太奇和特效副本。

运行时生成必须允许 Auto Possess AI 的 Spawned 或 Placed in World or Spawned；实际生成后验证 Controller、Blackboard 和正在运行的 BrainComponent。血条绑定通用 EnemyCharacter，不假设角色一定继承某个蓝图子类；校验先初始化引用，再绑定事件，且复用不重复绑定。

## 5. 预警与伤害一致

普通单体攻击默认感叹号；范围、位移攻击显示真实红色作用范围；特殊技能可两者并用。预警先于首次危险，锁定前跟随、锁定后固定。预警与伤害共用范围定义与遮挡结果。

Free_Spells 特效需检查空间、缩放参数、循环和寿命；命中粒子不能冒充精确判定边界。实际模型上核对插槽/地面投影位置。正常结束、取消、死亡和回收都清理提示与循环表现。

Niagara复制后先显式请求编译，再轮询至 completed/ready_to_run，保存后进行真实渲染验证。组件处于active或工具请求成功都不等于粒子可见；同时检查数据接口初始化错误。捕获PIE时确认截图来自游戏视口，独立PIE窗口下编辑器视口截图不是游戏证据。

## 6. 每次生命的清理

使用最新池的回收/唤醒合同，保留非池化分支。死亡只结算一次；停止 AI、取消技能/延迟任务、清理目标和临时状态。用生命租约与攻击代次阻止旧回调伤害或结束新生命。恢复属性、动画、碰撞和移动，不重复授予技能或遗留冷却。持续效果与投射物须单独规定来源死亡后的行为。

召唤来源不要借用Pawn的Owner：AI Possess会将Owner改为Controller。使用独立来源弱引用和生命租约；死亡/销毁委托幂等移除，房间登记先撤销再销毁。导航投影只证明点在网格上，承诺可达时还需检查完整路径。

## 7. 分层验证与接入

| 层次 | 必须提供的证据 |
|---|---|
| 资产 | 编译/保存/独立读回，骨骼、Slot、配置、控制器、血条引用正确 |
| 逻辑 | 正常攻击、冷却拒绝、无效目标、友军、边界和遮挡；打断/死亡不留下未来伤害 |
| 实机 | 动态生成启动行为树、导航追逐、真实移动姿态、蒙太奇播放与实际扣血 |
| 生命周期 | 至少两次生命，旧回调隔离、无重复死亡奖励、无残留提示/GE/委托 |
| 视觉 | 真实接触、预警可读性、范围和时间、血条；NullRHI不能替代 |

在对应测试通过后才修改游戏名单或精英/Boss入口；保持怪物总量、池容量和原有分配策略，备份接入配置。恢复测试前地图、视角与编辑器设置，不丢弃用户未保存修改。

交付文档记录参数、资源路径、测试结果、未覆盖边界和逐技能 PIE 验收步骤。自动化通过与用户视觉验收分别记录；未通过或未执行的阶段不能标成完成。
