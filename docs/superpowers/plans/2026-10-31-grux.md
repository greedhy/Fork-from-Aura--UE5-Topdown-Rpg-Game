# Grux Boss 实施计划

沿用用户确认的怪物扩展顺序与持续开发授权，传统Actor/GAS。遵循 monster-development-standard.md；源动作证据见 grux-animation-audit.md。具体数值在独立数据资产调节。

## 设计边界

复用 TelegraphedEnemyCharacter、ASC、选择器、伤害通路、范围投影与租约。双斧采用左右独立片段组成两段，每段先预警并重新锁定，单段每目标一次伤害；斧刃扫掠覆盖扇区时使用红色扇区，不以普通单体提示掩盖范围。冲锋先显示实际路径，锁定后服务端扫掠移动；末段挑飞有新的落地区域预警，不能把冲锋和挑飞计成无提示二次攻击。咆哮无直接伤害，感叹号后施加有时限、自身专属增益，死亡/取消/回收清理句柄。

默认Boss不加入普通池；仍验证显式池化后的两次生命。保留原Boss入口，直到逻辑、表现与自动化通过后替换，不增加Boss数量。源Paragon示例玩家与源素材不修改。

## 执行任务

1. 动画与资源：`Scripts/GA/author_grux_animations.py` 创建独立AS/AM；复用通用速度驱动结构建立专属AnimBP，删除玩家依赖。`setup_grux_animation_probe.py`/`run_grux_animation_probe.py` 记录真实双斧、脚部和蒙太奇输出，截图核对武器接触后再固定时序。
2. 配置与GA：新增Grux专属数据资产类型与三个GA；共享执行器只增加必要的可扩展阶段钩子、路径形状，旧配置默认行为保持不变。先写形状/阶段/增益句柄清理回归，再实现。
3. 角色与资产：独立BP、速度/伤害/AI配置、动画/特效副本；服务端选择器授予三GA，所有攻击沿用统一阵营/房间边界。动画采样与正式技能时序写回设计记录。
4. 运行验证：逐技能正常伤害/增益、预警、取消、墙体、无效目标、死亡及两次生命；冲锋不得越墙或越房间，连击取消不继续下一段，咆哮不叠加或跨生命残留。
5. 集成与交付：原有恶魔/萨满/StoneGolem/池回归，动态AI及移动姿态，Boss房间真实通关；独立审查后接入BossClass，提供用户PIE验收步骤。

## 当前证据

- 源根位移采样为零，冲锋必须显式控制移动。
- 已创建5份独立攻击AS/AM，源哈希保持不变。
- 源Grux AnimBP在普通Character下出现除零警告且加载示例玩家依赖；不能作为可交付敌人AnimBP直接复用。
- 已完成三个GA、独立数据资产、动画与Boss入口接入；真实战斗、生命周期、AI及Boss房间验证通过。最终参数、证据与待验收边界见 [Grux实现](../../grux-implementation.md)。
