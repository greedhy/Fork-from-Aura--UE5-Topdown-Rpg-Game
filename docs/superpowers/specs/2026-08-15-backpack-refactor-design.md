# 背包重构设计

## 目标

将现有背包重构为由稳定槽位驱动的系统：容量可随等级、扩容道具和装备加成动态变化；格子支持选中、使用和拖拽交换；背包可在不销毁数据的情况下打开、关闭并复用 UI。UI 优先采用 UE 5.8 MVVM，减少编辑器蓝图配置。

## 范围与规则

- 初始容量默认为 16 格，最终容量由角色成长、扩容道具与装备加成汇总后设置。
- 扩容在数组尾部增加空槽；缩容从尾部裁剪槽位。被裁剪的非空槽内物品直接丢弃。
- 单击非空格选中物品；单击空格取消选中。
- 使用按钮仅在已选中且可使用的物品时启用。使用成功后按物品行为返回的实际消耗量更新槽位。
- 拖拽到另一有效槽位时交换两个槽位内容，允许与空槽交换。拖拽取消或在无效区域松开时不修改数据。
- 打开背包时游戏继续运行，显示鼠标并使用“游戏与 UI”输入模式。关闭时移出视口并恢复纯游戏输入。
- 背包满时不创建新槽位；若同类物品的已有堆叠仍有空间，则允许部分存入，余量留在世界物品中。

## 数据模型

### 物品定义

创建 `UItemDefinition` 数据资产（或等价的主数据资产），作为每种物品的唯一静态定义。它包含：

- `ItemId`、显示名称与图标；
- `bAutoPickup`：重叠时是否自动请求拾取；
- `bStackable` 与 `MaxStack`：堆叠规则；
- `bUsable` 与可选的使用效果/行为引用。

运行时槽位只保存物品 ID 和数量；显示信息及规则始终由定义资产解析。这样不会把图标、堆叠规则等静态数据复制到每个槽位。

### 槽位和背包

用固定长度的 `TArray<FInventorySlot>` 取代紧凑的物品数组。`FInventorySlot` 表示一个稳定格子，保存空槽状态、`ItemId` 和数量。数组下标即 UI 槽位索引，不会因添加、使用、移除或交换而压缩。

`UInventoryModel` 是唯一的规则与状态所有者，提供：

- `SetMaxSlots(NewMaxSlots)`：扩展或裁剪尾部槽位并广播容量/内容变化；
- `TryAddItem(ItemId, Quantity)`：先填充同类未满堆，再填空槽，返回实际接收数量；
- `SwapSlots(From, To)`：校验两个索引后原子交换；
- `UseItemAt(Index)`：校验槽位和定义，触发使用行为并按成功的消耗结果更新；
- 查询、选中无关的删除及清空接口。

世界拾取物根据 `TryAddItem` 的返回数量更新自身余量：自动拾取在重叠事件发起请求，非自动拾取在交互事件发起同一请求。零接收时，世界物品保持不变。

## MVVM 与 UMG 边界

`UMVVM_Backpack` 订阅 Model 的容量和内容通知，维持与 `FInventorySlot` 数量完全一致的槽位 ViewModel 池；它不拥有背包事实数据。`UMVVM_InventorySlot` 暴露图标、数量、空槽、选中、可使用、拖拽源和拖拽悬停状态。

UE 5.8 的绑定保持严格同类型：

- 文本控件绑定 `FText` 属性或返回 `FText` 的转换 Getter；
- 可见性/可交互性绑定 `bool` 属性或 `bool` Getter；
- 图像控件绑定纹理对象（或与控件要求相符的同类型属性）。

所有绑定字段使用 `FieldNotify`，并在状态变化后精确广播。格式化（如容量文本、数量文本）位于 C++ ViewModel 的同类型转换函数中，不在蓝图中拼接或转换。

UMG/Widget 只处理 MVVM 不适合的边界：点击与拖拽事件、`DragDropOperation` 创建、添加/移出视口、以及玩家控制器输入模式。它们只调用 ViewModel 请求方法，绝不直接修改 Model。

## 交互与生命周期

打开请求会创建或复用 `UBackpackWidget`，确保 `UInventoryModel` 和 `UMVVM_Backpack` 已初始化并同步当前容量与内容，然后添加到视口。Widget 引用被缓存，关闭仅 `RemoveFromParent`，不销毁 Model 或 ViewModel；下次打开复用实例并再次同步。

格子单击调用 `SelectSlot(Index)`。拖拽开始、悬停、落下和取消分别调用 ViewModel 请求接口，ViewModel 负责校验索引、维护暂态视觉状态并最终调用 Model 的交换操作。使用按钮调用 `UseSelectedItem()`，由 ViewModel 解析当前选中索引并委托 Model。

## 错误处理

- 无效索引、空槽使用、不可使用物品、无效拖放和无选中项全部安全失败，不改变数据。
- 容量必须非负；缩容严格按尾部槽位丢弃，不重新排序保留物品。
- 添加物品可部分成功；未接收数量由世界物品保留。
- 每次 Model 成功变更后广播内容更新；容量变化额外广播容量更新，以使 VM 和 UI 保持同步。

## 验收与测试

- 容量因升级、扩容、装备加成增加与减少时，槽位数量与尾部丢弃规则正确。
- 同类物品按定义资产的堆叠规则合并；部分接收保留世界余量；满包且无可叠加空间时拒绝拾取。
- 选中、取消选中、使用按钮状态和使用后的数量/空槽更新正确。
- 非空与空槽之间、两个非空槽之间的拖拽交换正确；取消及无效落点无副作用。
- 打开、关闭、再次打开时 UI、输入模式、MVVM 绑定与背包数据均正确，且不会重复创建无用 Widget。
- 在 UE 5.8 编辑器中验证所有绑定的源/目标类型完全一致，无蓝图转换节点依赖。
